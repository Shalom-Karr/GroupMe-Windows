01

The thing GroupMe never built

GroupMe has no message search. Not on the web, not on the phone, not anywhere. The search box you already know only filters the chat list by conversation name — it has never once looked inside a message. This client archives your history locally and puts an SQLite FTS5 index over the whole of it, so the address someone sent you two years ago is a few keystrokes away instead of an hour of scrolling.

    02

    Three parts, one file

    It is not a reimplementation of GroupMe. It is the real thing with an archive bolted underneath it, and a reader that takes over when the network goes away. All three parts share a single SQLite database.

    Part i — Online

    The real client

    The window loads web.groupme.com in a webview. Sending, uploads and emoji are unchanged, because they are still GroupMe's own code doing them.

    web.groupme.com
    Part ii — Archive

    A worker writing it down

    A Rust worker calls api.groupme.com/v3 directly in the background and writes messages, conversations and media into a local SQLite database.

    api.groupme.com/v3 → SQLite
    Part iii — Offline

    A reader over the archive

    When the network drops, the window switches to a bundled reader served from that archive — messages, cached images and avatars, and the search index.

    %LOCALAPPDATA%
    03

    What it will not do

    Stated up front, because you should know before you install it rather than after.

    ×

    Offline is read‑only. You cannot send.

    This is deliberate and structural, not a feature somebody forgot. A queue that silently fires your messages into a conversation hours later is a worse product than a disabled composer. Offline, you can read everything; you cannot send.

    ×

    Search lives in the offline reader.

    The full‑text index is queried from the bundled reader. That is where search currently is.

    ×

    It is unofficial.

    This is an unofficial client. It is not affiliated with, endorsed by, or supported by GroupMe or Microsoft.

    04

    How it works

    Three steps, and only the first one asks anything of you.

    1. Sign in to GroupMe, normally

      Open the app and sign in the way you always do. It is GroupMe's own web client in the window, so there is nothing new to learn and nothing new to trust with your password.

    2. It archives in the background

      A Rust worker pulls your history from the GroupMe API and writes messages, conversations and media into a local SQLite database, indexing the text as it goes.

    3. Lose your connection, keep your history

      Drop off the network and the window switches to the local archive: every conversation, cached images and avatars, and full‑text search over the lot.

    The archive is the product. The webview is just the most honest way to keep sending messages while it fills up.

    06

    Where your data actually sits

    An app that copies your entire message history onto your disk owes you a straight answer about where it puts it. Here it is, including the part that is not flattering.

    • Your token

      Your access token is stored in Windows Credential Manager. It is never written into the database and never into a config file.

    • Your archive

      The archive is an unencrypted SQLite file in %LOCALAPPDATA%.

      Read this twice

      Anyone with access to your Windows account, or to your disk, can read every archived message and view every cached image. There is no password on the file. If that matters to you — and for a full copy of your message history it probably should — use BitLocker or another full‑disk encryption.

    • The network

      Nothing is sent anywhere. The app talks to GroupMe's API and nothing else. There is no telemetry, no analytics, and no server belonging to this project — there is no project server to send anything to.
